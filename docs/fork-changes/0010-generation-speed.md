# 0010：回合与近期平均生成速度

状态：维护中。

## 动机与行为

在 TUI 的回合完成信息末尾显示一个平均速度，例如 `• 42.3 token/s`。
回合完成值只在正常完成且至少有一组有效请求样本时显示；失败、中断或没有有效样本时隐藏。
执行中的状态行另显示近期平均值，例如 `42.3 token/s (5m)`，有样本时在流式输出期间也保留状态行。
不增加配置项、CLI 参数或 app-server 协议字段。

这里的速度是客户端观测的**模型请求平均吞吐**，不是服务端纯解码速度。
它包含网络、排队、输入处理及接收流期间的客户端处理时间，排除请求之间的
工具阻塞、等待用户输入和上下文压缩时间。工具与模型请求重叠时不再减去工具耗时。
不同回合不混用客户端时间与服务端时间，因此不依赖 WebSocket 专属计时字段。

## 计量口径

每次普通模型请求在调用 `ModelClientSession::stream` 前启动单调时钟，
在收到 `ResponseEvent::Completed` 时立即停止，早于该完成事件后的处理与工具等待。
把这一响应的原始 `output_tokens` 与该请求时间配对；它包含 reasoning 和工具调用参数，
不把 `reasoning_output_tokens` 明细再加一次。只统计本回合的普通采样请求，
不混入压缩等辅助请求，也不汇总子代理的响应。

回合平均速度为：`Σ 有效请求的 output_tokens / Σ 有效请求的 request_duration_seconds`，
不是各次速度的算术平均，也不是回合总用量除以回合墙钟时间。
它只代表本回合可完整计量的模型请求，不代表全部请求的实际 Token 消耗。
显示一位小数；会显示为零的极慢速度也隐藏。

请求缺失用量或在完成前被丢弃时，同时排除该请求的输出 Token 和耗时，
保留中断前后其它有效样本；整个回合没有有效样本时隐藏速度。
请求出现负数、重复/空响应 ID、耗时无效或统计溢出时，该回合统计整体失效。
底层 HTTP 请求、鉴权恢复、WebSocket 连接或请求失败也通过客户端内部失败计数检测，
避免一次 `stream` 内部重试成功掩盖未知尝试；发生这类失败时，排除该次 `stream`
对应的整个计量窗口，因为无法把成功响应的用量与失败尝试的耗时准确拆开。
计量窗口内同一客户端的并发辅助请求失败时，也保守排除该窗口，保留其它有效请求；
后续请求以新的计数快照开始，不受旧失败影响。
daemon 恢复未完成回合时，恢复前的请求没有可靠单调时钟数据，因此该回合不显示速度。
`end_turn=false` 表示还需要继续采样，不代表终止事件中的用量失效。
正常完成的响应，以及已收到终止事件和有效用量的回合内中断响应，均计入请求时间和输出 token；
被丢弃、没有收到终止事件或缺失用量的请求不参与平均速度计算。
尚未结束的请求、没有输出 token 的回合不产生回合完成值。

## 执行中的五分钟窗口

窗口限定在当前回合，以单调时钟累计普通模型请求进行中的时间；工具独占执行、
等待用户、请求间隔和压缩期间不推进。工具与模型请求重叠时，仍按模型请求时间推进，
同一时刻的重叠请求不重复推进窗口。

只选择有效时间轴上最近 300 秒内结束的有效请求，按
`Σ output_tokens / Σ 完整请求耗时` 计算，不平均各次 TPS，不截取单次请求的一部分。
一次请求即使持续超过五分钟，结束时仍整笔计入；其进行中会推进窗口，但不贡献样本。
例如 LLM 请求 30 秒、工具执行半小时、LLM 请求 30 秒，窗口只推进 60 秒。
进行中的请求超过五分钟时，旧样本会逐一到期，窗口为空时隐藏，等待该请求结束后重新显示。
恰好位于 300 秒边界的完成样本仍保留。

近期样本逐个校验：缺失权威用量、丢弃、底层失败、负数用量、空／重复响应 ID 或无效耗时的请求
不参与分子与分母，但实际请求等待仍推进窗口；保留异常请求前后的有效样本。
回合完成值仍保留原有整轮完整性校验；daemon 恢复的回合隐藏近期值。
有权威零输出的请求参与平均，允许显示 `0.0 token/s (5m)`；不使用文本长度估算。
每次开始新回合清空窗口，历史回放不重建近期样本，原有回合完成值保持原口径。

## 本地持久化与恢复

core 在发布正常完成事件前，将可靠结果写入本地状态库的
`fork_generation_speeds_v1` 私有表，键为 `(thread_id, turn_id)`。
保存原始输出 token 总数、请求耗时微秒，以及对应完成事件的开始时间、完成时间、回合耗时。
TUI 只在这三个完成字段均存在且与当前事件逐项一致时采信统计，缺失或不一致则隐藏。
即使写锁导致旧统计清理失败，恢复后的完成信息也不会直接采信仅有同一回合 ID 的旧记录。
恢复启动及无效回合结束时清除同回合的旧统计，避免崩溃发生在统计落库与完成事件持久化之间时误用旧值。
私有表使用幂等建表，不占用上游的 SQL migration 编号，避免上游增加同号迁移时冲突。

TUI 在初始恢复、切换会话、重连及处理实时完成事件时读取统计。
内嵌服务与本机 daemon 共用本地状态库；远程连接明确不读取本机数据。
每个会话最多保留最近 1000 条统计，删除会话时通过外键级联删除；
较旧或没有统计的历史回合不显示速度，不从日志或文字长度反推。
写入最多等待 200 毫秒，读取最多等待 100 毫秒；存储不可用时隐藏，
不把可选指标的错误变成回合错误，也不要求开启调试遥测。

近期值通过 `fork_live_generation_speeds_v1` 私有表供内嵌服务与本机 daemon 的 TUI 共用，
每个会话只留一份瞬时快照；不写入历史完成值，不传给远程客户端。
普通回合启动时先重置快照，使用独立运行标识拒绝旧后台任务覆盖恢复后的新快照。
新会话的线程元数据尚未落库或数据库暂时不可用时，后台重试初始化，不因首次写入失败放弃整个回合。
core 后台每秒以单调时钟计算窗口并发布快照；TUI 后台每秒读取，读写均限制为 100 毫秒，
不在流式处理或 UI 输入循环中等待数据库。回合任务结束或被取消时停止发布。
快照附带心跳，超过三秒未更新或时间异常时隐藏；墙上时间只用于判断发布任务是否仍存活，
不参与五分钟窗口的样本筛选或 TPS 计算。
读取还要求心跳晚于 TUI 本次观察到回合启动／恢复的时间，避免写锁阻止重置时展示崩溃前快照。
异步读取结果绑定本次本地回合生命周期，拒绝恢复前或切换会话前发起的读取结果。

## 验证与上游同步

纯计量测试覆盖加权聚合、缺失用量在有效请求之前/之间/之后的排除、
丢弃请求前后有效样本的保留、全部请求不可计量，以及无效值的整回合保护。
core 集成测试验证完成事件到达时统计已可读取，后续缺失用量的回合不生成新统计，
以及底层 HTTP 重试成功后的计量窗口排除。
state 与 Python SQL 测试覆盖跨连接读取、会话隔离、无效值约束、留存及删除。
TUI 测试覆盖完成信息、历史恢复、会话隔离、本机 daemon、远程连接及存储缺失。
SQLite 持锁测试验证清理超时后旧记录仍可被读取，而完成身份不一致时不能展示；
TUI 同时覆盖实时与历史恢复时拒绝旧完成身份。
Rust 测试在 fork CI 运行；本机只做格式、静态核对与 SQL 脚本测试，不运行重型构建。

近期值测试覆盖工具期间暂停、按完整请求耗时加权、长请求与边界到期、不可计量请求仍推进窗口、
零输出、重叠请求、权威用量接入，以及后续请求尚未结束时已能跨连接读到近期值。
SQLite 与 TUI 覆盖恢复重置、旧运行写入隔离、心跳过期、流式期间展示、窄屏截断和新回合清空。
恢复回归覆盖新鲜旧快照在 WAL 写锁下重置失败时的读取拒绝，以及相同 turn 恢复后的异步结果隔离。

诊断时在结构化日志中按 thread/turn 筛选 `codex.generation_speed.*` 事件或
`generation speed` 消息。请求终止日志包含 response ID、`end_turn` 和输出 token；
失效日志区分恢复、负数用量、重复/空 ID、零耗时及溢出；
请求排除日志区分用量缺失、客户端失败计数变化及未完成请求丢弃。
回合汇总、保存/清理及其完成/失败/超时、TUI 读取条数和完成行匹配结果也会记录。
日志使用 INFO，复现无需启用 TRACE；不记录请求、响应正文或凭据。
回归覆盖 `response.completed(end_turn=false)` 与 `response.incomplete(interrupted)`
在有/无用量时分别计入或排除该请求、同时保留后续有效样本的行为。

同步上游时重点核对普通采样的 stream/Completed 边界、工具等待的位置、回合失败/中断路径、
本地状态库初始化与外键行为，以及 TUI 的完成事件、会话恢复、重连和历史分页入口。
近期值还依赖回合任务拥有的发布任务生命周期、UI 后台轮询与流式状态行显示边界。
若上游增加可靠的官方速度信息，应重新评估这项改造，不同时显示两个口径。
