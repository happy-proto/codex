# 异步压缩生命周期诊断

## 动机

网关记录压缩请求完成，不代表客户端已接受结果。后台压缩失败、候选过期和安装后
仍超预算都会影响前台回退；缺少关联日志时无法区分这些路径。

## 行为与入口

- [后台任务与检查点](../../codex-rs/core/src/session/async_compaction.rs) 显式携带
  thread、turn、模型、历史版本和前缀长度的 tracing span，记录启动、结果生成与
  通道交付、失败、检查点消费、接收器关闭、等待及等待结束。失败日志说明同一
  尝试能否重试和退避时间；只追加历史不会使尝试去重键变化。
  [退避重试](0019-async-compaction-retry.md) 为每次请求增加序号，启动日志记录重试次数。
- [响应收集](../../codex-rs/core/src/compact_remote_v2.rs) 在输出校验前记录响应 ID、
  输出总数和可识别的压缩项数量，区分服务端完成与客户端接受。
- [候选安装](../../codex-rs/core/src/compact_remote_v2_installation.rs) 与
  [原子历史替换](../../codex-rs/core/src/session/mod.rs) 记录模型、压缩 hash、历史
  版本、前缀长度及认证所有者是否变化，并记录安装后的预算状态和实际前台请求。
- 生命周期事件统一使用 `codex_core::async_compaction` target，携带稳定 `stage`
  字段；只记录标识、计数、耗时、兼容性判断和已有错误描述，不记录对话或加密正文。

本改造不调整阈值、计数、重试、候选校验、历史替换或前台回退行为。

## 验证与维护

通过已构建 app-server 与隔离的本地 Responses 模拟服务验证失败、成功和前台回退，
检查生命周期事件能关联到同一 thread。既有异步压缩场景由 CI 验证行为不变。
实际事件保留仍受日志数据库的分区容量限制；thread 关联不等于无限期留存。

上游同步时关注后台任务是否已继承 tracing 上下文、是否新增等价生命周期事件。
保留能区分响应完成、候选生成、候选消费与实际安装的证据，避免重复记录高频轮询。
