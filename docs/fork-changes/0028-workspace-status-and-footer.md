# 0028：分栏任务状态与共享底栏

状态：维护中。

## 动机与行为

启用实验性 `tui_workspace` 并在宽终端打开 side 时，两个对话都保留任务状态行。
未聚焦侧也随后台通知显示运行、等待输入、等待审批、完成、失败、中断或关闭；
计时归线程所有，切换焦点不重置，等待交互时暂停，结束后冻结。
状态行始终占用一行，任务完成不会收起该行。
最新回合结束后，固定状态行复用普通回合 `Worked for…` 的缩进、淡色和 ` • ` 分隔，
显示同一条完成记录中的耗时、完成时间、运行指标及经完成身份校验的最终生成速度。
窄栏只裁切为一行，不换行增加输入区域高度；不再单独拼接 `• Completed · …`。
正文不再重复绘制该回合末尾的 `Worked for…`。源记录仍保留，旧回合及单栏视图正常展示。
后台回合完成前也读取所属线程的最终速度记录，不以最后一次实时采样代替最终速度。
side 使用临时会话的独立数值指标通道，保留不创建对话历史的行为；
统计与生命周期约束见 [0009](0009-generation-speed.md)。
运行状态复用原有状态组件，保留呼吸动画、计时、聚焦侧的中断提示与生成速度；
未聚焦侧也独立轮询本地实时速度，不随另一侧进入空闲而停更。
只绘制状态组件的首行，详细上下文和 hook 换行不会改变输入区域的高度。
窄侧栏优先缩短中断提示，为计时和速度保留空间；同一 turn 恢复时刷新速度采样身份，
丢弃恢复前的回调和缓存，但不重置累计计时。

两侧使用同一 BottomPane / ChatComposer 测量及绘制草稿，切走后不再把输入框压成三行。
常规草稿和任务状态的高度不随焦点改变；输入弹窗、附件预览等仍按各自实际内容布局。
未聚焦侧不显示中断快捷键，不接受输入；待答、待处理消息和其它线程审批等交互预览
仅在聚焦侧显示，避免停放状态未同步时留下过期提示。
两侧正文同时接收所属线程的新通知，未聚焦侧继续增量展示消息、工具事件和流式输出。
保留源文本供宽度变化时重新排版，流式内容完成后合并为完整消息。
切回时仍以线程快照与缓冲通知重建前台；不把后台投影再拼入重放结果。

模型、项目、会话信息和快捷键提示共用窗口底栏，内容取自当前聚焦对话。
通常占两行；搜索和复制菜单按原有提示内容增加一行，保留完整操作说明及查询光标。
分隔线到共享底栏上方结束。窄终端沿用单对话界面。
沿用上游分隔线拖拽调宽与未聚焦正文的选择、复制、链接和滚动交互；
拖拽身份使用完整窗口尺寸，绘制区域扣除共享底栏，避免底栏高度使拖拽提前失效。
点击未聚焦输入框时，从实际绘制的 BottomPane 读取光标，再切换到对应对话。

## 入口与维护约束

- `tui/src/app/side_pane.rs`：分栏及共享底栏几何，未聚焦侧绘制。
- `tui/src/app/owned_transcript.rs`：聚焦侧布局及共享底栏绘制。
- `tui/src/app/thread_events.rs`、`thread_routing.rs`：线程状态、计时和后台更新。
- `tui/src/app/side_projection.rs`、`app_event_sender.rs`：后台展示投影、历史事件路由与隔离。
- `tui/src/bottom_pane/workspace_status.rs`：紧凑任务状态展示。
- `tui/src/history_cell/separators.rs`：普通回合与分栏共用的完成元数据及样式。
- `tui/src/status_indicator_widget.rs`：单行渲染复用原状态动画及提示。
- `tui/src/app/generation_speed.rs`：两侧实时速度轮询及回调归属校验。
- `tui/src/bottom_pane/chat_composer/`：测量、光标及底栏共用布局。

保留上游单个可交互 ChatWidget 的结构；停放的 widget 只展示原订阅收到的通知，
其输入队列禁止自动提交，sender 只允许按线程及投影编号路由的历史写入、合并和流式 tick。
旧投影的延迟事件不能写入重新创建的 pane，不建立第二条订阅或重复发送线程操作。
语音仍只有原 background voice owner 接收实时通知，展示时借用它的当前状态，结束后转存为普通投影。
后台通知按实时语义处理，避免将 reasoning 增量与完成事件误作快照重放而重复展示。
投影不写终端标题、程序状态和工作目录；这些全局终端信息只由聚焦侧更新。
语音 owner 转存时复制重放缓存，保留尚待历史提交的末条字幕供投影完成提交。
同步上游时注意输入恢复先于 BottomPane 转移、历史事件的 FIFO 屏障及源文本合并；
后台审批和输入请求仍由原请求路由处理。

窄屏与短屏，并验证后台消息、投影事件归属和旧投影隔离。默认分支 CI 运行这些测试；
