# 0021 服务端重试等待提示

状态：维护中。

## 为什么改

发布版默认隐藏第一次 WebSocket 重连提示。服务端通过 `Retry-After` 要求等待时，
同一逻辑也会隐藏数分钟的限流退避，使客户端持续显示工作中却没有进展说明。
传输回退原本也在等待结束后才发出提示。

## 如何改

带服务端等待建议的重试始终先通知客户端，并显示预计等待秒数。
WebSocket 回退至 HTTPS 时同样先提示再等待。没有等待建议的首次短暂重连仍沿用上游提示策略。
重试预算、服务端期限、容量重试和取消行为保持原有约束；心跳存活不代表模型已有进展。

## 入口和验证

- [共用重试](../../codex-rs/core/src/responses_retry.rs)。
- [单元回归](../../codex-rs/core/src/responses_retry_tests.rs)：首次重试及传输回退在休眠前提示，并遵守原期限。
- [协议回归](../../codex-rs/core/tests/suite/retry_after.rs)：模拟 WebSocket 限流后先发出等待提示，再重试并完成。
- 发布产物使用隔离 app-server 与本地模拟 provider 验证：首次限流等待可见、重试不早于期限、完成请求；连接重置、响应超时和上传中断后仍可继续处理回合。

## 上游同步

上游若调整首次重试提示策略，保留服务端退避的可见性和原始等待期限。
不要通过缩短退避、刷新等待期限或把协议心跳当作业务进展来消除等待。
