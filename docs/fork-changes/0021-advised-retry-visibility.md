# 0021 服务端重试等待提示

状态：维护中。

## 为什么改

发布版默认隐藏第一次 WebSocket 重连提示。服务端通过 `Retry-After` 要求等待时，
同一逻辑也会隐藏数分钟的限流退避，使客户端持续显示工作中却没有进展说明。
传输回退原本也在等待结束后才发出提示。

## 如何改

Responses 共用重试在等待前通知客户端，带服务端建议时始终显示；
没有等待建议的首次短暂重连仍沿用上游提示策略。WebSocket 回退至 HTTPS 时同样先提示再等待。

TUI 在输入框上方原有状态行显示 `Retrying in 1m 55s (1/100)`，每秒更新剩余时间，
到期后显示 `Reconnecting...`，后续通知到达后恢复原有状态。关闭动画时仍刷新倒计时，保留中断快捷键。
倒计时使用现有 `Reconnecting... (retrying in Ns)` 通知文本，从接收时刻计时；
显示精度为秒，不新增协议字段，也不延后、截短或重置 core 实际等待的期限。

容量无限重试已移除，重试预算、服务端期限和取消行为沿用上游；心跳存活不代表模型已有进展。
这些提示覆盖共用 Responses 重试循环，底层 HTTP 自身的请求重试仍沿用上游行为。

## 入口和验证

- [共用重试](../../codex-rs/core/src/responses_retry.rs)。
- [单元回归](../../codex-rs/core/src/responses_retry_tests.rs)：首次重试及传输回退在休眠前提示，并遵守原期限。
- [协议回归](../../codex-rs/core/tests/suite/retry_after.rs)：模拟 WebSocket 限流后先发出等待提示，再重试并完成。
- [TUI 状态行](../../codex-rs/tui/src/status_indicator_widget.rs)：覆盖倒计时、到期、恢复、重复等待、窄终端和关闭动画。
- 发布产物使用隔离 app-server 与本地模拟 provider 验证：首次限流等待可见、重试不早于期限、完成请求；连接重置、响应超时和上传中断后仍可继续处理回合。

## 上游同步

上游若调整首次重试提示策略，保留服务端退避的可见性和原始等待期限。
不要通过缩短退避、刷新等待期限或把协议心跳当作业务进展来消除等待。
