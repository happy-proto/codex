# 改造记录和日常交付

先读 [AGENTS.md](../../../../AGENTS.md) 和 [编号索引](../../../../docs/fork-changes/README.md)，
确认 `origin` 指向 `happy-proto/codex`、默认分支为 `fork`，再 fetch 并核对本地与远端状态。

以 `git diff main..fork` 和当前源码确认差异，不把旧 PR 描述或文档当作行为证据。
已有改造从索引找到对应记录，修改代码时同步更新动机、实现边界、入口和验证信息；
新改造取现有最大编号加一，用中文描述最终行为，避免记录临时调试过程。
记录上游关联和维护注意事项，但不把编号绑定到 commit SHA；后续修正继续更新原文件。

本轮开始时按 upstream 参考确定上游 alpha 候选。
在 `fork` 完成已授权的代码和文档变更，做与风险匹配的检查；
提交前核对范围，使用英文 Conventional Commit，保留用户已有改动。
没有 PR 创建步骤，不运行 `gh stack`；只有用户另行要求时才创建 PR。

推送前保存远端期望 SHA。普通更新使用快进推送；
同步上游需要改写历史时，先演练并验证，再使用明确旧 SHA 的 force-with-lease。
推送后核对远端 `main`、`fork`、默认分支和最新提交的 CI；不把排队或运行中当作通过。

文档只证明维护记录存在。代码、CI、发布产物和本机安装分别验收并报告，
上游吸收或删除改造时删除对应记录、更新索引并重新编号；记录不写“状态”行。
